# Card picker deviations

Status: **Finalized for this implementation.**

This file records every intentional difference between the seven reference screens in
`design/Card Picker.dc.html` and the shipping implementation. The reference package itself is
otherwise unchanged.

| ID | Source value or behavior | Implementation | Why |
| --- | --- | --- | --- |
| D01 | The prototype `BEST` map supplies hand-written subtitle strings. | Every held-row, search-result, and catalog-tile subtitle is computed from production reward rates by `bestForCard()`; no `BEST` copy ships. | User decision: an unverified reward claim is worse than omitting a card. The app's maintained rates are the source of truth. |
| D02 | Raw transparent PNG card art, roughly 1200×757 and roughly 670 KB each. | Each of the 28 production cards ships as transparent WebP at 112×71 and 360×227. There is no PNG fallback. | User-approved optimization. Both sizes preserve the 1.586 ratio to the nearest whole pixel and cover the 58×37 and roughly 180px render widths at 2×. Alpha was programmatically verified on all 56 files. |
| D03 | The browse grid shows all twelve tiles, including the empty Hotel shelf. | A browse tile renders only when its production shelf contains at least one card. Hotel is hidden today; Airline and Other remain; no tile shows a count; fixed ordering is preserved and Other remains last. | User decision: an empty page ending in only Custom card is a dead end. The tile returns automatically when production data gains a matching card. |
| D04 | Inline markup uses `overflow:hidden` on the filter-chip row. | The row uses `overflow-x:auto`, no wrapping, hidden scrollbar, contained overscroll, iOS momentum scrolling, and focus-driven `scrollIntoView()`. | Source conflict resolved in favor of README behavior. Fixed-width, no-wrap chips otherwise become unreachable. |
| D05 | Filter chips are visually about 30px tall; their markup has no separate touch geometry. | Each chip has a real 44px target. Its source-sized surface is drawn inside that target; `margin:-7px 0` preserves the reference's vertical placement without overlapping the title or list targets. | Repository requirement: touch targets are at least 44×44 CSS px. This also prevents the scrolling container from clipping a pseudo-element-only target. |
| D06 | The drag glyph occupies a 16px-wide box. | The reorder button is a non-overlapping 44×44 target with the 16px glyph centered at the same x-position; a `-14px` end margin uses the list's existing right inset. | Repository touch-target requirement and independent accessibility review. |
| D07 | The plus is 38×38; search clear is 18×18; Add/Create pills and the custom-card text link use their drawn dimensions. | The visible dimensions remain unchanged. Invisible, owned hit areas make the plus 44×44, search clear 44×44, Add/Create pills at least 44px high, and the custom-card link 44px high. | Repository touch-target requirement. These hit areas are not visible and do not alter screenshots. |
| D08 | Light secondary text is `#6b7280`; placeholder/tertiary text is `#9ca3af`. | Light secondary and placeholder text use `#69717f`. | `#9ca3af` is only 2.54:1 on white, and `#6b7280` is 4.43:1 on `#f4f5f7`. The replacement is 4.51:1 or better on the picker backgrounds used for meaningful small text. Logged instead of silently retaining inaccessible design values. |
| D09 | Dark mode is not specified. | Dark values are: background `#0f1115`; surface `#191c22`; alternate field `#20242b`; primary text `#f3f4f6`; secondary `#aeb6c2`; placeholder `#818b99`; border `#626b78`; placeholder fill `#22262e`; placeholder border `#697381`; accent `#3b82f6`; accent hover `#60a5fa`; primary action `#1d4ed8`; primary hover `#2563eb`; accent tint `#1e2a4a`; accent-on-tint `#a5b4fc`; success `#34d399`; success fill `rgba(52,211,153,.14)`; search highlight `#5f4b16`; header glow `rgba(59,130,246,.12)`; logo shadow `rgba(59,130,246,.45)`; focus ring `rgba(59,130,246,.24)`; clear fill `#46505d`; clear text `#f3f4f6`; inactive-nav fill `rgba(174,182,194,.08)`; nav shadow `rgba(0,0,0,.38)`; active-nav shadow `rgba(59,130,246,.38)`; logo backing `#ffffff`. | User requested dark mode and asked that every dark value be logged as design-unspecified. `#818b99` also reaches 4.51:1 on the darkest alternate field. |
| D10 | Search-results markup is a finite static sample with no scrolling behavior. | Every production name match remains in the DOM inside a 336px maximum-height (six-row) scrolling region. | User decision and README behavior: all matches must remain available, never hard-capped at six. |
| D11 | The interaction table says focusing search replaces browse; the static screens only show browse for empty input and results for a non-empty query. | Focus alone leaves the hub/browse grid in place. A non-empty trimmed query switches to live results; clearing restores browse and bottom navigation. | Explicit user decision: empty focused search restores the hub. Search still has no autofocus. |
| D12 | The search screenshot includes a 290px software-keyboard mock and omits bottom navigation. | The keyboard block is not implemented. While a non-empty search is active, bottom navigation hides so the real platform keyboard can occupy that space. | The README identifies the grey block as presentation, not app UI. The real iOS keyboard owns its dimensions and animation. |
| D13 | Push/pop behavior is named but a static file cannot specify duration, easing, or reduced motion. | Pages use 200ms, `cubic-bezier(.16,1,.3,1)`, and an 18px horizontal offset. The existing reduced-motion rule reduces it to 0.01ms. | Design-unspecified motion values chosen to provide a restrained platform-style transition while honoring reduced-motion preferences. |
| D14 | The mock's held-row body has no executable behavior. | Tapping a held row opens the existing rate editor; its separate reorder target remains independently operable. | User-approved behavior, now also stated in the handoff README. Logged because static markup itself is silent. |
| D15 | The interaction table leaves `✓ In my cards` as “No-op (or navigate…)”. | `✓ In my cards` / `✓ Added` is a non-focusable status element and a no-op, with the source visual treatment. | User decision: it is confirmation, not an invitation to edit one tap after adding. |
| D16 | The custom form's drawn controls are 42px (identity), 38px (rate rows), and roughly 34px (segmented-control surface). | Interactive boxes are 44px tall. Inset pseudo-surfaces retain the source's 42px, 38px, and 34px visible treatments. This makes the custom form roughly 22px taller overall. | Repository 44px touch-target requirement. |
| D17 | The custom-step screenshot represents card name, bank, and earn rates; earlier implementation work exposed browse metadata controls. | The UI contains only those three concepts. New custom records still carry `brand:null` and `hotel/store/biz/other:false`; those values normalize through import/export but do not place a personal card in shared catalog shelves. Issuer remains available for the user's own wallet chip. | Latest user decision: shared brand/category metadata is catalog curation, not a one-user custom-card question. |
| D18 | The prototype uses source-order static card arrays and placeholder copy. | The picker has an explicit, tested 28-ID production order matching the design catalog. It deliberately differs from the underlying app database order for the Amex shelf. | Keeps all picker shelves and search results faithful without reordering production rewards data used elsewhere. |
| D19 | The static held-list wrapper reserves 100px below the list for an absolutely positioned tab bar. | In the iOS scroll-shell layout, the list reserves 19px inside the scrolling region while the real fixed tab bar contributes the remaining roughly 81px; non-iOS layout retains 100px. | Existing app navigation is fixed outside the scroll container. The effective clearance and 390×844 visual endpoint match the reference while avoiding nested iOS scrolling bugs. |
| D20 | Focus behavior, announcements, pointer cancellation, edge scrolling, and Browser Back/Forward cannot be demonstrated in the static markup. | Focused rate fields receive the same 1.5px accent/3px-ring treatment as other fields; search announces result counts; rate rows have numbered accessible names; pointer cancellation is a no-op; dragging targets live row midpoints and auto-scrolls at a 44px edge zone by 10px/frame; browser history restores every tab correctly. | Behavioral implementation required for WCAG 2.2 AA and reliable platform navigation. |
| D21 | Adding a card is illustrated only by the in-place status change. | The old pulse and long coaching toast are retired; the action changes to status in place and a screen-reader live message confirms the add. | User decision: the My cards priority hint carries the needed coaching without an earned interruption. |
| D22 | The seven reference frames are fixed at 390×844. | The values are matched at 390×844; the same components also reflow at 320px, desktop widths up to the app's existing 560px content maximum, and a 195px CSS viewport used to emulate 200% phone zoom. | Design-unspecified responsive behavior required by the repository. The 44px device frame, canvas color, device border, and device shadow are intentionally absent because the handoff declares them presentation only. |
| D23 | Search and card-name mocks draw a 1.5×18px caret. | Real `<input>` controls use the platform caret with `#2563eb` / the dark accent as `caret-color`; its exact width and height are browser-controlled. | A fake caret would not track selection, editing, composition, or accessibility correctly. The mock caret is a static-prototype artifact. |
| D24 | The tab bar has 28px bottom padding. | It uses `max(28px, 7px + env(safe-area-inset-bottom))`; the 390×844 desktop render resolves to 28px, while a device with a larger home-indicator inset receives additional clearance. The app header similarly uses `max(54px, env(safe-area-inset-top))`. | Required safe-area behavior on iOS; the design's device frame cannot model each browser/standalone safe-area environment. |
